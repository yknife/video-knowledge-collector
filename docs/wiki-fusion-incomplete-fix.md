# Wiki 融合变更集未提交：诊断与修复

针对任务 `job_01790304984477462400_6326306b83` 的只读审计，原有 `WIKI_AGENT_INCOMPLETE` 表示 Hermes 模型回合结束时没有**通过校验**的 `wiki_submit_changes`。模型并非完全没有调用工具：最近一次失败回合中调用了三次提交，均被拒绝。旧审计仅存异常类型，无法从历史报告确定每次拒绝的具体字段。

在当前数据库和 Wiki 的**隔离副本**上复现，捕获到“引用了本轮未读取的来源”和“比较页缺少两个独立来源”。另一轮真实模型复现中，模型两次引用了真实片段 ID，但填入的毫秒时间与这些片段不符；该轮在修正后成功提交，副本 Wiki 修订从 27 到 28，真实 Wiki 未被修改。模型响应还多次触发 4096/8192 token 输出截断与续写，增加了工具调用不完整的概率。

修复内容：

- 将 `wiki_submit_changes` 的 `pages → claims → evidence` 参数结构、页面类型和主张类型写入工具 schema；提示模型先读取所有要引用的来源，只有两条独立来源时才建比较页，并优先提交一页、少量新主张。既有页的主张由编译器保留，无需模型重复输出。
- 将融合回合输出上限提高到 8192 token。模型若仍未提交有效变更集，任务错误和审计会带上**最后一条静态校验原因**，便于定位；来源正文、凭据和模型输出不会进入审计错误字段。
- 引用片段 ID 仍须来自已确认的来源快照；页面时间范围改由这些真实片段确定，不再信任模型填写的毫秒值。伪造片段 ID、错误来源身份、缺乏独立来源的比较页仍会被拒绝。

定向测试覆盖错误原因传递、失败时不提交、真实片段时间规范化；完整仓库检查通过。Worker 已重启并加载修复。原任务通过状态机重新入队后，在第 7 次尝试成功，生成 Wiki 提交 `wc_e93506414ffa4a3aa67e8c7d1ea6e122`，页面 `concept_browser_automation_glove_standard`；隔离复现未修改用户 Wiki。
